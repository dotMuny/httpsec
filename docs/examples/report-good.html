TLS and certificates

highServer accepts cipher suites without forward secrecy

3 accepted suites use static RSA key exchange: TLS_RSA_WITH_AES_128_CBC_SHA256, TLS_RSA_WITH_AES_128_GCM_SHA256, TLS_RSA_WITH_AES_256_GCM_SHA384.

Why it matters. Static-RSA key exchange means a single future compromise of the private key decrypts every session ever recorded. ECDHE removes that risk.

How to fix it — Restrict TLS 1.2 to AEAD suites with forward secrecy and let the server pick the order.

Nginx

ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305;

lowOCSP stapling is not enabled

No stapled OCSP response was returned in the handshake. A direct OCSP query returned status good.

Why it matters. Without stapling the client either skips revocation checking or leaks which site it is visiting to the CA, and pays a round trip for it.

How to fix it — Enable OCSP stapling so the handshake carries a fresh revocation proof.

Nginx

ssl_stapling on;
ssl_stapling_verify on;
ssl_trusted_certificate /etc/letsencrypt/live/example.com/chain.pem;
resolver 1.1.1.1 9.9.9.9 valid=300s;

Apache httpd

SSLUseStapling On
SSLStaplingCache "shmcb:/var/run/ocsp(128000)"

Security headers

lowNo Cross-Origin-Opener-Policy header

No Cross-Origin-Opener-Policy header, so cross-origin documents can retain a window reference to this page.

Why it matters. Without COOP a page you open, or that opens you, keeps a window reference across origins. That reference is the basis of tabnabbing and of several XS-Leaks.

How to fix it — Send Cross-Origin-Opener-Policy: same-origin to isolate the browsing context group.

Nginx

add_header Cross-Origin-Opener-Policy "same-origin" always;

Apache httpd

Header always set Cross-Origin-Opener-Policy "same-origin"

Caddy

header Cross-Origin-Opener-Policy "same-origin"

Cloudflare / generic CDN

# Transform Rule -> Set static -> Cross-Origin-Opener-Policy: same-origin

Use same-origin-allow-popups if the site opens OAuth popups that need window.opener.

https://developer.mozilla.org/docs/Web/HTTP/Headers/Cross-Origin-Opener-Policy

lowNo Permissions-Policy header

No Permissions-Policy header, so camera, microphone, geolocation and payment keep their default availability.

Why it matters. Powerful features stay available to the document and, in some cases, to embedded third-party frames. Denying what you do not use limits what injected or embedded code can reach.

How to fix it — Send Permissions-Policy denying the features the site does not use.

Nginx

add_header Permissions-Policy "accelerometer=(), camera=(), geolocation=(), gyroscope=(), magnetometer=(), microphone=(), payment=(), usb=(), interest-cohort=()" always;

Apache httpd

Header always set Permissions-Policy "accelerometer=(), camera=(), geolocation=(), gyroscope=(), magnetometer=(), microphone=(), payment=(), usb=()"

Content Security Policy

lowstyle-src allows 'unsafe-inline'

'unsafe-inline' is allowed for stylesheets.

Why it matters. Inline styles enable CSS-based data exfiltration and UI redressing. It is much less severe than inline script and is often impractical to remove, but it is not free.

Evidence
style-src 'unsafe-inline' github.githubassets.com
How to fix it — Remove 'unsafe-inline' from script-src and adopt per-request nonces with 'strict-dynamic'.

Nginx

# 1. Generate a nonce per request and place it on every <script> tag.
# 2. Then drop 'unsafe-inline' (keep it only as the CSP1 fallback shown here):
add_header Content-Security-Policy "script-src 'nonce-$csp_nonce' 'strict-dynamic' https: 'unsafe-inline'; object-src 'none'; base-uri 'none'" always;

Apache httpd

Header always set Content-Security-Policy "script-src 'nonce-%{CSP_NONCE}e' 'strict-dynamic' https: 'unsafe-inline'; object-src 'none'; base-uri 'none'"

Caddy

header Content-Security-Policy "script-src 'nonce-{http.vars.csp_nonce}' 'strict-dynamic' https: 'unsafe-inline'; object-src 'none'; base-uri 'none'"

Cloudflare / generic CDN

# Nonces cannot be produced by a static header rule. Use a Cloudflare Worker:
#   const nonce = crypto.randomUUID().replace(/-/g,'');
#   res.headers.set('Content-Security-Policy', `script-src 'nonce-${nonce}' 'strict-dynamic' https: 'unsafe-inline'`)
# and inject the same nonce into the HTML with HTMLRewriter.

'unsafe-inline' is ignored by CSP3 browsers when a nonce is present, so keeping it is safe and helps old clients.

https://www.w3.org/TR/CSP3/#directive-style-src

csp.style-src.unsafe-inline

Cookies

mediumCookie is missing the HttpOnly flag — _octo

Cookie _octo is readable from JavaScript.

Why it matters. Without HttpOnly the cookie is readable from JavaScript, so any XSS turns directly into credential theft.

Evidence
_octo=REDACTED; expires=Fri, 24 Sep 2027 10:18:42 GMT; domain=.github.com; path=/; secure; SameSite=Lax
How to fix it — Set Secure, HttpOnly and an explicit SameSite on every cookie, and use the __Host- prefix for session cookies.

Nginx

# nginx can only rewrite cookies it proxies:
proxy_cookie_flags ~ secure httponly samesite=lax;
# Preferably set the attributes in the application, e.g.:
#   Set-Cookie: __Host-session=...; Path=/; Secure; HttpOnly; SameSite=Lax

Apache httpd

Header always edit Set-Cookie ^(.*)$ "$1; Secure; HttpOnly; SameSite=Lax"
# Or, for the session cookie of a specific module:
#   php_value session.cookie_secure 1
#   php_value session.cookie_httponly 1
#   php_value session.cookie_samesite Lax

Caddy

# Caddy does not rewrite cookies; set the attributes in the upstream application:
#   Set-Cookie: __Host-session=...; Path=/; Secure; HttpOnly; SameSite=Lax

Cloudflare / generic CDN

# Cloudflare Transform Rule cannot safely rewrite Set-Cookie. Fix it in the origin application:
#   Set-Cookie: __Host-session=...; Path=/; Secure; HttpOnly; SameSite=Lax

__Host- requires Secure, Path=/ and no Domain attribute, which pins the cookie to exactly one origin.
